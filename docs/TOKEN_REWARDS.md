# Token Rewards

## Adventure milestone — 2026-10-05

Reward treasury funds are separate from the payment/burn treasury. DEV_MODE plus MOCK_TOKEN_MODE permits a clearly labelled local TEST$MOCHI pool and atomic mock payout. Production starts disabled until explicit reward prices, account/global caps, minimum account age, verified wallets and a separate funded treasury are configured. Currency identity pins mint, decimals, network and wallet to the ledger. Sale and claim check finalized on-chain wallet holdings against recorded backing. Claims batch unassigned owned accruals into one pending claim; production does not automatically sign or transfer tokens. An operator executes the exact transfer externally, then records its finalized receipt using npm run rewards:record -- payout CLAIM_ID SIGNATURE. Verified funding uses npm run rewards:record -- funding FUND_ID SIGNATURE SENDER AMOUNT_RAW and memo mochi:FUND_ID; payout memo is mochi:CLAIM_ID. Receipt validation binds signer, sender/recipient owner, mint, decimals, amount, memo, time and signature. Funding, accrual and payout records are immutable except a one-time owned claim assignment. Never configure a fabricated production pool or reuse the payment wallet. Production transfer automation remains future work.
