# Current painterly isometric asset pipeline

The main world uses original project-bound raster atlases under
`web/assets/isoworld/`. `manifest.json` gives cell order and provenance;
`PROMPTS.md` records the prompt set and built-in imagegen workflow. No supplied
reference images or external game art were copied. Old GLB instructions below
are retained for historical tooling, not the active Town renderer.

## Scene construction and scale

Author scenes in logical XY coordinates, independent of browser dimensions.
50 logical units remain one metre of the prior convention. Town is 57×48m;
other room bounds stay unchanged. Screen projection is x=(worldX−worldY)×0.72,
y=(worldX+worldY)×0.36. Inverse projection is used for clicks; server routing
uses the original coordinates. Fixed camera translation/zoom never changes nav.
Human art is 124 projected world pixels tall; beast art is 83, before camera
zoom. Preserve foot contact under the idle/walk transform.

## Categories and naming

`buildings-vN.png`: 4×2, café/exchange/arcade/observatory and four pavilions.
`props-vN.png`: 4×2 trees/foliage/fountain/bench/table/wall/lamp.
`characters-vN.png`: 4×4, four human/beast archetype rows, four facing columns.
`terrain-vN.png`: 2×2 overhead sandstone/meadow/cobbles/water tiles.
Keep original sheets immutable, version siblings and update manifest/loader.
Ground patterns are projected into one 3072×2048 scene texture at room creation.
The first three atlases remove disconnected alpha cell bleed in memory, trim to
the largest silhouette, share each repacked source, and anchor bottom center.
This is a generated-art bridge; artist exports should provide explicit trim,
foot anchors and pivots to eliminate runtime extraction and directional jitter.

## Layer and depth contracts

1. Ground/background: painted turf, broad paving/roads, lawns and distant roofs.
2. Sorted objects: buildings, props, actors, pets and residents. zIndex is
   projected foot Y, with tiny tie bias. Tall art extends upward from its foot.
3. Effects: destination marker, developer overlays; fountain rings share its depth.
4. DOM UI: projected foot-to-head name/bubble anchors, bounded text and visibility.

Long walls/foliage should be separate segments with individual foot depths;
never export a whole foreground district as one unsortable billboard. Current
foreground props fade locally if they hide the player; this changes no collision.

## Collision, walkability and routes

`isoworld/layout.js` owns Town bounds/buildings/trees/landscaping.
`game/town.js` owns stalls/NPC routes/interactions. `game/model.js` derives shared
footprint collisions; visible sprite dimensions never become authority. Footprints
must leave a valid entrance approach and ≥350 logical units between stall centres.
The cached NavigationService uses a logical 20-unit grid and tested segment
checks. NPCs use authored walk/pause targets and server-synced clocks. Arrival
players spread to nearby valid anchors; declared companion follow spacing is
95 units to the side and 40 forward. This is gameplay safety, not brain learning.

## Optimization and animation handoff

Share atlas sources, cap DPR at2, draw ground once, cull offscreen entities and
update NPC targets at2–5Hz. Current PNGs total roughly9MB; texture compression,
versioned HTTP caching and offline atlas packing remain production priorities.
Ship a compressed format with PNG fallback only after server MIME/cache support
and target-device QA. Current human sprites have four facing poses with bob/sway;
there are no full skeletal/walk-frame sets. Cosmetic layers retain owned slot
contracts; base style currently combines hair and skin rather than independent
sliders. Future artist atlas should provide separate body/hair/clothing layers,
8 directions and 6–8 walk frames plus idle/emote/care states.

# Original 3D asset pipeline

The included models are original rigged prototypes, generated by `npm run assets:models`.
No artwork from another social game is used. Source: tools/build-models.mjs. Output:
web/assets/models/penguin.glb and mochi.glb. Scene architecture keeps model replacement
separate from sockets, ownership, navigation, care, dialogue and Cadence.

## Blender handoff

Use meters, +Y up after glTF export, forward +Z, feet at origin. Penguin height2m,
Mochi height1m. Apply scale; keep one armature and unique named bones per character.
Export selected mesh/armature to GLB with skinning, normals and named action clips.
Do not bake lights into avatar colors. Author softened silhouettes/bevels and restrained
rough materials. Keep mesh origins and attachments consistent through outfit variants.

Socket names: head_socket, face_socket, chest_socket, back_socket, left_hand_socket,
feet_socket. The renderer's CosmeticAttachments mounts individual reusable accessories
onto named THREE.Bone socket objects. Socket transforms are independent of each outfit.
The prototype skin carries root/head deformation; current accessory sockets belong to
its outer presentation rig. Artist replacement should move them onto the exported
animated armature and adapt the attachment resolver, preserving these names.

Penguin clips: idle, walk, wave, dance, cheer, laugh, sad, sit.
Mochi clips: idle, follow, happy, sad, excited, sleep, eat, play, look, hop.
Included GLBs contain named prototype head motion clips; expressive walk/emote/care
motion currently also uses procedural transforms. These are not final artist animations.
ModelAsset clones skeletons per entity, shares cached source geometry, clones materials,
selects named clips with AnimationMixer and crossfades. Asset failure retains the original
procedural fallback. Only two essential character models load; other rooms are built on
entry from reusable scene components.

## Budgets and folders

Artist targets (not current measured guarantees): penguin8k triangles, pet4k, cosmetic1k,
room150k; textures512/1024px, reuse atlases. Keep mobile LODs at quarter triangle count.
Use avatars/penguin/{base,hats,face,tops,back,hands,feet}, mochi/{base,accessories},
world/{town,cafe,park,market,arcade,exchange,arena,lab,home} under web/assets/models.
Record author/license in each asset folder. Validate every GLB animation/socket and
render in Town before replacing another scene. Keep original source .blend separately.

Use KTX2/Basis for artist textures and Draco/meshopt where useful. Configure local decoder
URLs, not unexplained external CDN dependencies. Current prototypes have no texture atlases
or compression decoder dependency. Instanced flowers demonstrate repeated-prop batching;
other repeated assets should be merged/instanced before the40-player GPU milestone.
Low quality disables realtime shadows and caps DPR1; medium caps1.3; high caps1.8 and
uses2048 shadow maps. WebGL2 is tested. WebGPU/TSL migration is deferred until materials,
shadowing and devices have a compatible validation matrix.

References: [Three GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html),
[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html),
[R3F performance guidance](https://r3f.docs.pmnd.rs/advanced/scaling-performance).

## Town benchmark kit (October 2026)

Town materials live in `web/js/world3d/materials.js`. Preset names are `stone`,
`paintedWood`, `wood`, `brass`, `metal`, `glass`, `fabric`, `foliage`, `water`,
`plaster`. Use cream stone, teal/blue paint, terracotta/coral cloth, warm timber,
and restrained brass. TownPart, benches, lamps, trees, signs, awnings and Goods
are reusable geometry; other rooms have not received the Town expansion.

Current maps are original deterministic 128×128 tiles. Stone has staggered grout;
timber has directional grain; cloth has a subtle weave. Each mapped family shares
one base-color/normal/roughness/AO set across tint variants. Base color is sRGB;
normal, roughness and AO remain linear. Normal amplitude and AO are restrained.
Do not replace intentional surfaces with noisy/grungy maps. Painted signs use
768×128 original canvas typography, world meshes, and share normal material language.
The 64×64 contact-shadow gradient is shared across all characters. No borrowed
images, HDRIs, recordings or third-party art were added.

Artist texture targets: hero buildings 1024–2048px; ordinary props 256–1024px;
characters 1024px (2048 only with a measured benefit). Never use 4K for a tiny prop.
Atlas shop signs/posters into a shared 1K sheet on an art pass; use one trim sheet
for roof edges, window frames, brass borders and counters. Preserve UV density
around 128–256 texels/m for the default view. Current procedural tiles are shared,
not an already completed artist trim-sheet/atlas pipeline. KTX2/Basis remains the
recommended export path when artist textures are introduced.

### Coordinates, pivots and contact

One world unit is approximately one meter. Logical coordinates use 50 units/m:
world X = (logical X−600)/50, world Z = (logical Y−500)/50. Penguin body is about
2m tall; Mochi metadata scales its original roughly 0.94m body to 0.9, leaving it
about 40–50% of the player with accessories. Residents use the same proportions
at 0.83 scale. Counters are 1.25m, benches around 0.6m, lamps around 2.8m.
Doors and future replacement rigs should be reviewed against the 2m player,
with at least 2.4–3m clear height. The retained prototype doors are still tight;
final building assets should improve that clearance.

Export +Y up/+Z forward and apply artist transforms, but do not assume an imported
pivot is at the base. `grounding.js` measures the rendered visual's world-space
Box3, refreshes skinned bounds, and moves only its visual child until minY equals
the sampled contact plane plus a declared hop. Entity X/Z remains authoritative;
entity Y is the terrain contact height. `GroundedVisual` accepts optional config
`{groundOffset, scale, rotationOffset:[x,y,z]}`. Default correction is automatic;
art overrides belong in metadata, never scattered gameplay offsets. Separate
food/play props from body contact bounds. Hop motion is explicit; cosmetic root
motion must not become world movement. Included clips have no position/root-motion
tracks. Future locomotion clips should be exported in place or have translation
tracks isolated during asset import.

Ground meshes alone carry `userData.walkableGround=true`. A downward ray ignores
stalls, roofs, water, NPCs and benches. No-hit returns null and holds the entity's
last contact height while geometry loads. Town's floor is Y=0.025; its accessible
ramp rises continuously to Y=0.6. Decorative platform sides are not walkable rays.

### Collision, navigation and LOD

Keep decorative meshes separate from simple logical collision footprints in
`game/model.js`. Town uses its own bounds (−300…1500, 100…900); other rooms retain
their old bounds. Props should include approach positions reachable around their
footprints. Test routes to every vendor after layout changes. The shared cached
20-unit navigation grid and server recomputation are authoritative; the debug
points are a walkability grid, not an exported polygon navmesh. Platform rails
block side approaches; the north ramp is the intended access. Server seating owns
bench occupancy/pose and returns walking to the validated approach point.

Residents are config-driven in `game/town.js`; their authored routes are separated
and checked against collision. Nearby presentation updates at 5Hz; distant poses
at 2Hz and omit walking secondary motion. Residents use shared low-poly geometry
rather than twelve animated brain/skeleton hosts. Flower beds instance 160 flowers
in one draw. Hero penguin/Mochi skins keep independent mixers and named sockets.
No full skeletal crowd/GPU animation system has been introduced. Before 40-player
release, add measured artist character/building LODs and batch repeated trim/props.

### Lighting and bake workflow

Default is a warm afternoon sun, soft cool fill, hemisphere contribution,
subtle window/lamp emissive materials, and a gradient sky with original clouds
and a distant street silhouette. Medium uses one 1024² directional shadow map;
high uses 2048²; low omits realtime shadows but keeps soft contact gradients.
There are no per-stall point-light shadows. Development controls compare an
evening key preset, free camera, material swatches, terrain/model bounds and routes.
Foreground shop/stall groups fade when a camera ray would hide the player or pet.

No lightmaps are baked currently. If introduced, export UV2 with non-overlapping
islands, bake only static indirect illumination, and keep animated actors, direct
sun shadows and readable signage separate. Measure bake atlas memory and validate
both quality presets before shipping. Do not bake arbitrary time-of-day color into
base color maps or edit an immutable brain pack as part of environment art work.

Frame order is explicit: skin mixers at −3, entity/procedural poses at −2,
contact correction at −1, then camera/render work. This keeps grounding on the
current pose rather than relying on component subscription order. Negative
priorities preserve Fiber's automatic rendering; see [Fiber frame ordering](https://r3f.docs.pmnd.rs/api/hooks#negative-indices).
Resident bubble/label React updates run on a timer; the pose loop stays imperative.

## Locomotion frames — 2026-10-05

The current primary renderer uses actual eight-frame walk sets rather than static-pose sway. `web/js/isoworld/WalkFrames.js` bakes original painted upper bodies and articulated alternating legs into a fixed untrimmed 8-column ×16-row atlas (128 frames). Each row is archetype×4 + diagonal direction (SE, SW, NW, NE); each column is gait phase×8. Two villagers, Moonfox and Woodland Deer are included. Ground pivot is (0.5, 156/180) in 160×180 source cells. Rendering normalizes to the recorded source-body height, not a changing trimmed silhouette. Eight logical directions retain phase and map to four art directions until artist replacements exist.

`web/assets/isoworld/locomotion-v1.json` records the contract; developer World diagnostics → Preview walk frames exposes the source atlas. The temporary rig draws real hip/knee/foot changes, grounded stance and lifted swing; code-native leg detail is explicitly prototype art. Human stride is 105 logical units/loop; Mochi 82. Ground contact displacement is projected consistently with that distance. Future artist sprites should retain original rectangles, pivots and trim offsets and implement the same rows/archetype/direction texture interface. Do not run silhouette trimming on individual walk frames. Foot-contact hooks are at phase 0 and 0.5; surface audio can be extended later.

The generated original `walk-rig-v1.png` is checked in and loaded by the renderer with `locomotion-v1.json`. The metadata records source-body heights for stable scale across directional frames. Startup validates dimensions/pivots; automated checks verify all 128 frame rectangles and reject malformed metadata. The generator remains available in WalkFrames.js for future rig adjustments.

### Full-body animation v2

See [ANIMATION_DELIVERY.md](ANIMATION_DELIVERY.md) for all current sets/limits and
[ANIMATION_PROMPTS.md](ANIMATION_PROMPTS.md) for original built-in imagegen prompts.
`animation/registry.js` defines stride, direction order, body type, anchors and
states. PNG+JSON atlases preserve sourceSize, spriteSourceSize and pivots;
`npm run assets:register` registers these provisional irregular source grids,
`npm run assets:validate` rejects missing/out-of-bounds frames/pivots. Build runs
validation automatically. Artist sheets may replace the PNG/JSON pair without
changing movement; eight-view exports use the registry's eight logical row order.
Appearance sheets precompose synchronized existing equipment placeholders with
painted base outfits; local cells192px, NPC/remote128px, maximum eight caches.
No cloth simulation or additional procedural legs. Future cosmetic layers must
export identical direction/frame/canvas/pivot registration before compositing.

### Gameplay action atlases v1

See [ACTION_ANIMATION_DELIVERY.md](ACTION_ANIMATION_DELIVERY.md) for action
state/event contracts, provisional generated art, aliases, validation and renderer
performance. Action/reaction PNG siblings use the same 224px logical canvas,
(.5,.88) ground pivot and (.5,.12) logical head anchor. `tools/register-actions.mjs`
registers source pixels without editing PNGs. Optional action exports provide
`states` (direction → eight source-frame indices), `requiredStates`, `height`,
`mirrors`, `sourceSize`, `spriteSourceSize` and `pivot`; loader failures retain
compatible locomotion. Renderer decisions remain exclusively authoritative.
